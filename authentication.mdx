Every request to OpenTweet — whether through the REST API or the hosted MCP server — must include an `ot_` API key. OpenTweet uses Bearer token authentication: include your key in a request header, and the platform identifies your account, checks your subscription, and enforces your plan's daily limits automatically.

## Sending Your Key

You have two equivalent ways to pass your key on each request. Use whichever header your HTTP client or framework makes easier:

```bash
# Option 1 — Authorization header (preferred)
curl -H 'Authorization: Bearer ot_your_key' https://opentweet.io/api/v1/me

# Option 2 — X-API-Key header
curl -H 'X-API-Key: ot_your_key' https://opentweet.io/api/v1/me
```

Both headers are accepted on every endpoint. The `Authorization: Bearer` form is preferred because it aligns with standard OAuth 2.0 conventions and is recognized by most API clients and code generators automatically.

## Verify Your Key

Before integrating further, confirm your key is valid and your subscription is active by calling `GET /api/v1/me`:

```bash
curl -H 'Authorization: Bearer ot_your_key' https://opentweet.io/api/v1/me
```

A successful response looks like this:

```json
{
  "authenticated": true,
  "subscription": { "has_access": true, "status": "active" },
  "limits": { "can_post": true, "remaining_posts_today": 17, "daily_limit": 20 }
}
```

| Field | Description |
|-------|-------------|
| `authenticated` | `true` if the key is valid and recognized. |
| `subscription.has_access` | `true` if your plan is active (trial or paid). |
| `subscription.status` | `"active"`, `"trialing"`, `"canceled"`, or `"past_due"`. |
| `limits.can_post` | `true` if you have remaining posts in today's allowance. |
| `limits.remaining_posts_today` | Number of posts you can still publish before midnight UTC. |
| `limits.daily_limit` | Your plan's maximum posts per day. |

## Creating and Managing Keys

Create and revoke API keys from the **Developer** section of your dashboard:

1. Open [https://opentweet.io](https://opentweet.io) and sign in.
2. Navigate to **Dashboard → Developer → New API Key**.
3. Give the key a descriptive name (e.g., `ci-pipeline` or `my-agent`).
4. Copy the key immediately — it is displayed **only once** at creation time and cannot be retrieved later.

Your plan determines how many keys you can hold simultaneously: 3 on Pro, 10 on Advanced, and 25 on Agency.

## Rotating Keys

Rotate a key whenever you suspect it has been exposed or as part of a regular credential hygiene cycle:

1. Create a new key in the Developer section.
2. Update every integration, environment variable, or config file that references the old key.
3. Delete the old key from the dashboard once you've confirmed the new one works.

There is no downtime during rotation — both keys are valid until you delete the old one.

## Security Best Practices

<Note>
Store your `ot_` key in an environment variable (e.g., `OPENTWEET_API_KEY`) and read it at runtime. Never hardcode it in source code, commit it to a repository, or expose it in client-side JavaScript. API keys must be kept server-side only — treat them with the same care as a password.
</Note>

## MCP Server Authentication

For the hosted MCP server at `https://mcp.opentweet.io/mcp`, pass your key in the `Authorization` header inside your MCP client config:

```json
{
  "mcpServers": {
    "opentweet": {
      "type": "streamable-http",
      "url": "https://mcp.opentweet.io/mcp",
      "headers": { "Authorization": "Bearer ot_your_key" }
    }
  }
}
```

If you're running the local npm MCP server instead, set the `OPENTWEET_API_KEY` environment variable and the server will pick it up automatically — no header config needed.

## Common Auth Errors

| Status | Meaning | Fix |
|--------|---------|-----|
| `401` | Invalid or missing key | Confirm the key starts with `ot_`, is copied in full, and has not been deleted from the dashboard. |
| `403` | No active subscription | Subscribe to a plan or re-activate your 7-day trial at [opentweet.io](https://opentweet.io). |
| `429` | Daily post limit reached | Wait until midnight UTC when the counter resets, or upgrade to a plan with a higher daily limit. |
