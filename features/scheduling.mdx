OpenTweet gives you a single visual calendar where every post — whether you created it manually or an AI agent generated it — lives in one place. From that calendar you can schedule new posts, drag them to different time slots, and let OpenTweet's best-time heatmap suggest the moments your audience is most likely to engage.

## How the Visual Calendar Works

Every post you create lands on the calendar the moment it gets a scheduled date. Posts created by AI agents through the MCP or REST API appear on the same calendar, so you always have a complete picture of what's going out and when. You can view the calendar by day, week, or month to plan ahead without losing detail.

## Scheduling Options

OpenTweet gives you three ways to set a publish time:

### Best-Time Heatmap

The heatmap is built entirely from **your** engagement history — not a generic industry chart. After you've published enough posts, OpenTweet analyses the likes, replies, reposts, and clicks each post received and maps those results by hour and day of the week. Click **Suggest Best Time** in the composer and OpenTweet pre-fills the time field with the slot that has historically performed best for your account.

## Editing and Moving Scheduled Posts

You can move or edit any post right up until it goes live. Open the post from the calendar, update the text, media, or scheduled date, and save. Once a post has been published it becomes read-only, but everything in the queue stays editable.

## Bulk Scheduling

When you need to fill a whole week in one pass, bulk scheduling saves you the repetition:

- **Import via JSON** — Upload a JSON file where each object contains a `text` field and a `scheduled_date`. OpenTweet validates the file and drops all posts onto the calendar at once.
- **Generate with AI** — Use the AI Studio to generate a batch of posts on a topic, then assign dates to the entire set from the review screen.

## Daily Scheduling Limits

Scheduling limits apply to posts that are given a date (including immediate publishes). Drafts saved without a date do not count toward the limit.

| Plan | Posts per day |
|------|--------------|
| Pro | 20 |
| Advanced | 100 |
| Agency | 300 |

## Schedule a Post via the Dashboard

1. Open **Dashboard → Calendar**.
2. Click an empty time slot or select **New Post**.
3. Write your post in the composer.
4. Click **Schedule**, then choose a date and time — or click **Suggest Best Time** to use the heatmap.
5. Click **Confirm** to lock the post into the calendar.

To reschedule, drag the post card to a new slot or open it and edit the date field directly.

## Schedule a Post via the REST API

Pass a `scheduled_date` in ISO 8601 format to queue a post for future publishing:

```bash
curl -X POST https://opentweet.io/api/v1/posts \
  -H 'Authorization: Bearer ot_your_key' \
  -H 'Content-Type: application/json' \
  -d '{"text": "Launch day!", "scheduled_date": "2026-07-10T09:00:00Z"}'
```

### Reschedule an Existing Post

Send a `PATCH` to the post's `/schedule` endpoint with the new date:

```bash
curl -X POST https://opentweet.io/api/v1/posts/POST_ID/schedule \
  -H 'Authorization: Bearer ot_your_key' \
  -H 'Content-Type: application/json' \
  -d '{"scheduled_date": "2026-07-11T09:00:00Z"}'
```

<Warning>
  `scheduled_date` and `publish_now` are mutually exclusive. Passing both in the same request returns a `400` error. Use `scheduled_date` to queue a post for later; use `publish_now: true` to publish immediately.
</Warning>

<Note>
  Scheduling a post — including rescheduling — counts toward your plan's daily limit the moment the date is set. Saving a post as a draft (no date assigned) does **not** consume any of your daily allowance.
</Note>
